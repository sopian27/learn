### Quiz

1. Task "brainstorm 5 pendekatan arsitektur buat sistem baru, belum ada constraint teknis" — cocok ideation atau eksekusi terstruktur? Sumbu mana yang paling nentuin?
   ideation , karena masih brainstorm. Banyak opsi valid biaya salah rendah, lalu constraints masih belum ada. karena eksekusi tersturkur constraints atau kebutuhan harus sudah jelas dan ketat.

2. Kenapa "model lebih pintar" bukan alasan valid buat pilih provider tertentu di sebuah task?
   Karena “model lebih pintar” tidak otomatis berarti provider tersebut paling cocok untuk task itu.
   Pemilihan provider seharusnya berdasarkan fit terhadap kebutuhan task, misalnya:
    1. **Task nature** — ideation/eksplorasi vs spec eksekusi.
    2. **Verifiability** — output butuh benar/salah objektif (kode, angka) vs subjektif/kreatif.
    3. **Kebutuhan tool/agentic** — perlu aksi nyata ke file/repo/environment, atau cukup teks?
    4. **Lock-in ekosistem** — kerjaan sudah hidup di mana (repo kode? Google Doc? Notion?) — jangan pindah tool kalau migrasi konteks lebih mahal dari manfaatnya.
    5. **Freshness/grounding** — butuh info live/terkini → pilih tool dengan search grounding kuat.
    6. **Cost/latency toleransi** — brainstorming: banyak iterasi murah oke. Eksekusi: model lebih mahal/lambat tapi presisi worth it.

### Exercise

Klasifikasikan 4 skenario — **Ideation-lean tool** (GPT-style) / **Eksekusi/agentic tool** (Claude-style) / **Research-grounded tool** (Gemini-style) — sebut minimal 2 sumbu keputusan per jawaban:

1. Bikin 8 variasi headline landing page buat A/B test, belum ada data performa.
    Ideation-lean tool (GPT-style)
    Task nature: ideation/eksplorasi — butuh 8 alternatif headline, bukan eksekusi spesifik.
    Verifiability: subjektif/kreatif — tidak ada jawaban benar-salah objektif.
    Cost/latency: idealnya banyak iterasi cepat dan murah.

2. Migrasi 40 file dari Java 17 ke Java 25 syntax, harus compile & test lolos.
    Eksekusi/agentic tool (Claude-style)
    Task nature: spec eksekusi — migrasi konkret dari Java 17 → 25.
    Verifiability: sangat objektif — harus compile dan test lolos.
    Tool/agentic: perlu membaca dan mengubah 40 file serta menjalankan build/test berulang.

3. Ringkas 200 halaman laporan riset kompetitor plus cari data pasar terbaru bulan ini.
    Research-grounded tool (Gemini-style)
    Freshness/grounding: sangat penting karena harus mencari data pasar terbaru bulan ini.
    Verifiability: data riset harus grounded pada sumber, bukan sekadar generasi dari model.
    Task nature: kombinasi document analysis + external research, sehingga retrieval/grounding lebih penting daripada ideation.

4. Debug race condition di service concurrent, butuh baca kode, ubah, jalanin test ulang berkali-kali.
    Eksekusi/agentic tool (Claude-style)
    Task nature: spec eksekusi — menemukan dan memperbaiki race condition.
    Tool/agentic: perlu baca kode → ubah → jalankan test → analisis hasil → ubah lagi.
    Verifiability: sangat tinggi karena keberhasilan harus dibuktikan lewat test dan perilaku sistem.
    Cost/latency: model/tool yang lebih mahal tetapi mampu melakukan loop debugging lebih layak karena presisi lebih bernilai.
