### Revisi 1 

1. Ego — Memisahkan kemampuan dari hak untuk dipilih

Jika saya merasa seharusnya saya yang mendapatkan kesempatan karena saya lebih senior atau merasa kemampuan saya tidak kalah dari orang lain, maka saya akan memisahkan fakta bahwa saya capable dari fakta bahwa saya dipilih, lalu mengarahkan energi saya pada kualitas kerja dan pengembangan kemampuan yang memang berada dalam kendali saya.

Evidence: 5.1.md — Exercise 5.1, momen saat saya tidak dipilih ke project baru, sementara teman teman saya melanjutkan ke project lain atas keputusan bos.

“harusnya sih saya, yang ke project baru, karena saya kan senior dan saya juga bisa ko, saya gak kurang dari teman-teman saya.”

Kemudian saya mengidentifikasi kesalahan kategorisasi: senioritas dan kemampuan ≠ hak untuk dipilih.

Kaitan lesson: Dikotomi kendali 5.1 + sinyal ego Lesson 1.4.

2. Ego — Tidak mengubah masalah menjadi ancaman terhadap diri

Jika terjadi masalah pekerjaan dan saya mulai berpikir bahwa orang lain seharusnya lebih teliti atau saya perlu membuktikan bahwa saya sudah melakukan bagian saya dengan benar, maka saya akan mengambil jarak dan mencari apa yang perlu diselesaikan, bukan apa yang perlu saya menangkan.

Evidence: 5.2.md — Exercise 5.2, bagian View from Above. Saya mendokumentasikan momen ketika masalah pekerjaan membuat saya fokus pada kesalahan orang lain dan muncul dorongan membela diri serta membuktikan bahwa saya sudah melakukan bagian saya dengan benar.

Setelah mengambil jarak, saya menyadari:

masalah tersebut sebenarnya hanya satu masalah kecil dalam sistem kerja yang lebih besar.

Kaitan lesson: View from Above 5.2 + self-distancing dan sinyal ego Lesson 1.4.

3. Feedback — Memisahkan feedback dari validasi

Jika saya meminta masukan seseorang yang sebelumnya mengerjakan flow yang sedang saya tangani dan mulai gelisah karena responsnya belum datang, maka saya akan mengingat bahwa informasi dari jawabannya berguna untuk pekerjaan, tetapi kecepatan atau keberadaan responsnya bukan ukuran apakah saya sudah cukup baik.

Evidence: 5.3.md — Exercise 5.3, saat saya bertanya kepada teman mengenai flow yang sebelumnya dia kerjakan karena task tersebut di-handover kepada saya. Saya memang membutuhkan feedback teknis, tetapi kemudian ada hal yang sadari bahwa kegelisahan juga berasal dari menunggu respons orang tersebut untuk merasa aman bahwa saya sudah melakukan hal yang benar.

Kaitan lesson: Feedback vs validasi eksternal + sociometer theory 5.3.

4. Feedback — Tidak berpura-pura sudah mendapatkan jawaban

Jika jawaban seseorang belum menjawab seluruh pertanyaan saya, maka saya akan menerima jawabannya dengan sopan tetapi tetap mengakui bahwa informasi saya belum cukup dan mencari informasi tambahan.

Evidence: 5.3.md — Exercise 5.3, ketika jawaban teman saya cukup normatif dan tidak sepenuhnya memenuhi ekspektasi. Saya tetap menjawab “ok”, padahal sebenarnya masih merasa ada informasi yang kurang karena ingin terlihat baik dan diterima.

Kaitan lesson: Enchiridion pasal 23 + pembedaan feedback fungsional dan validasi eksternal pada 5.3.

5. Kerja Keras — Fokus pada area yang bisa dikerjakan

Jika saya menghadapi outcome yang ditentukan oleh orang atau kondisi di luar kendali saya, maka saya akan mengerahkan usaha penuh pada kualitas pekerjaan, tanggung jawab, pembelajaran, dan pengembangan kemampuan saya.

Evidence: 5.1.md — Exercise 5.1, setelah tidak dipilih ke project baru. saya secara eksplisit mengidentifikasi hal yang masih berada dalam kendali saya: respons, sikap, kualitas pekerjaan existing, tanggung jawab, belajar, dan pengembangan kemampuan.

Kaitan lesson: Dikotomi kendali Epictetus 5.1.

6. Kerja Keras — Target tetap dipegang tanpa menggantungkan diri pada hasil

Jika saya mulai gelisah karena hasil yang saya inginkan belum terjadi, maka saya akan tetap mempertahankan target tersebut sebagai arah usaha, tetapi mengembalikan fokus kepada tindakan yang bisa saya lakukan sekarang.

Evidence: 5.4.md — Exercise 5.4, ketika saya mengaudit klaim “lepaskan kelekatan sepenuhnya ke hasil.” saya mengoreksinya menjadi: tetap peduli terhadap hasil, tetapi tidak menggantungkan harga diri dan ketenangan pada hasil tersebut.

Kaitan lesson: Sintesis dikotomi kendali 5.1 dengan Goal-Setting Theory 5.4.

### Revisi 2

### Menggunakan pengalaman untuk mengembangkan orang lain

Jika saya memiliki pengalaman atau pengetahuan teknis yang lebih tinggi daripada junior atau rekan lain dan saya melihat solusi mereka kurang tepat, maka saya akan bertanya mengenai reasoning mereka terlebih dahulu sebelum mengoreksi, sehingga pengalaman saya digunakan untuk membantu mereka berkembang, bukan untuk menunjukkan bahwa saya lebih benar.

Evidence: 5.2.md — Exercise 5.2, bagian Level 5 Leadership. Saya mengakui bahwa ketika lebih berpengalaman atau memahami bagian teknis tertentu, saya terkadang ingin langsung menunjukkan bahwa cara saya lebih benar.

Saya kemudian memberikan contoh perilaku yang ingin dilatih:

“Kenapa kamu memilih pendekatan ini?”

sebelum membantu menemukan kelemahan solusinya.

Kaitan lesson: Level 5 Leadership — Lesson 1.2.

### Memberikan kredit kepada orang lain

Jika saya berhasil menyelesaikan atau merilis sebuah feature dan mulai melihat keberhasilan tersebut sebagai hasil kemampuan atau usaha saya sendiri, maka saya akan secara sadar mengidentifikasi kontribusi orang lain yang ikut memungkinkan keberhasilan tersebut dan memberikan kredit kepada mereka.

Evidence: mini-project-3.md — momen release feature, ketika dalam refleksi saya mengakui bahwa keberhasilan tersebut bukan hanya berasal dari diri saya sendiri dan ada peran faktor lain, termasuk tim.

Jadi prinsip ini bukan berasal dari skenario “seharusnya kita menghargai tim”, tetapi dari refleksi nyata bahwa setelah release, saya menyadari keberhasilan tersebut memiliki kontribusi dari orang lain.

Kaitan lesson: Level 5 Leadership — Lesson 1.2, terutama pola tidak memusatkan keberhasilan pada ego pribadi dan mengakui kontribusi orang lain.
