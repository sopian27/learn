### Exercise / Task

Anda punya service yang, untuk tiap request, memanggil 3 API pihak ketiga secara **berurutan** (sekuensial) untuk verifikasi data pelanggan:

```java
public class CustomerVerificationService {

    public VerificationResult verify(String customerId) {
        CreditScore creditScore = creditBureauClient.fetch(customerId);       // ~200ms, network call
        FraudCheck fraudCheck = fraudServiceClient.check(customerId);         // ~150ms, network call
        AddressValidation address = addressServiceClient.validate(customerId); // ~180ms, network call

        return new VerificationResult(creditScore, fraudCheck, address);
    }
}
```

Total waktu per request sekarang ~530ms (dijumlah, karena berurutan) — padahal ketiga panggilan itu **tidak saling bergantung satu sama lain** (hasil satu tidak dipakai buat manggil yang lain).

**Tugas Anda:**

1. Refactor `verify()` supaya ketiga panggilan API itu dijalankan **paralel**, bukan sekuensial, menggunakan `ExecutorService` yang Anda buat sendiri (bukan `Executors.newFixedThreadPool` mentah — konstruksi `ThreadPoolExecutor` eksplisit dengan parameter yang Anda tentukan sendiri).

    ```java
    public class CustomerVerificationService {

        private final ExecutorService executor;

        public CustomerVerificationService() {
            this.executor = new ThreadPoolExecutor(
                    32,                      // corePoolSize
                    36,                      // maximumPoolSize
                    0L,
                    TimeUnit.MILLISECONDS,
                    new ArrayBlockingQueue<>(200),
                    new ThreadPoolExecutor.CallerRunsPolicy()
            );
        }

        public VerificationResult verify(String customerId) {

            Future<CreditScore> creditFuture =
                    executor.submit(() -> creditBureauClient.fetch(customerId));

            Future<FraudCheck> fraudFuture =
                    executor.submit(() -> fraudServiceClient.check(customerId));

            Future<AddressValidation> addressFuture =
                    executor.submit(() -> addressServiceClient.validate(customerId));

            try {
                CreditScore creditScore = creditFuture.get();
                FraudCheck fraudCheck = fraudFuture.get();
                AddressValidation address = addressFuture.get();

                return new VerificationResult(
                        creditScore,
                        fraudCheck,
                        address
                );

            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                throw new VerificationException("Verification interrupted", e);

            } catch (ExecutionException e) {
                throw new VerificationException("Verification failed", e.getCause());
            }
        }
    }
    ```

    Sequential:
    200 + 150 + 180 = ~530 ms

    Parallel:
    max(200, 150, 180) = ~200 ms

2. Tentukan ukuran pool untuk `ExecutorService` ini, dan **jelaskan alasannya** memakai rumus sizing dari Theory — sifat kerja di sini CPU-bound atau I/O-bound? Berapa perkiraan `W/C`-nya berdasarkan angka waktu di atas?
    
    Ini jelas I/O-bound karena sebagian besar waktu thread menunggu network response. Rumus nya :

    N_cpu = 8
    U_cpu = 1
    W = 530 ms
    C = 10 ms
    W/C = 530 / 10
        = 53

    N_threads = N_cpu * U_cpu * (1 + W/C)
    = 8 * 1 * (1 + 53)
    = 8 * 54
    = 432 thread

    Secara teori sizing menghasilkan sekitar 432 threads. Namun angka ini bukan berarti production harus langsung menggunakan 432 threads. Untuk exercise, saya memilih 32 threads sebagai starting point dan melakukan tuning berdasarkan load test, latency, throughput, connection pool, dan rate limit API.

    corePoolSize = 32
    maxPoolSize  = 36
    queue        = 200

3. Tulis kode yang mengumpulkan ketiga hasil (`creditScore`, `fraudCheck`, `address`) setelah semuanya selesai, dan jelaskan apa yang terjadi kalau salah satu dari ketiga panggilan itu melempar exception — apakah dua yang lain tetap harus ditunggu, atau boleh langsung gagal semua?
    Dengan kode di berikut :

    creditFuture.get();
    fraudFuture.get();
    addressFuture.get();

    Kalau misalnya creditFuture.get() gagal, verify() langsung melempar exception. Tapi dua task lainnya belum tentu berhenti. Mereka sudah ter-submit dan bisa tetap berjalan di thread pool.

    Jadi ada dua kebijakan:

    Fail-fast:
    Satu API gagal → hasil verification dianggap gagal. Cocok kalau ketiga data wajib.

    Wait-all:
    Tetap tunggu ketiga API selesai → kumpulkan semua success/failure. Cocok kalau ingin mengetahui status masing-masing API.

    Untuk case seperti ini, biasanya fail-fast secara business result, tetapi idealnya task yang sudah berjalan tetap dibiarkan selesai atau dibatalkan bila memang aman.
