### Exercise / Task

**Bagian 1 — Temukan & perbaiki.** Class berikut dipakai untuk menghitung sisa stok barang, diakses banyak thread (request) bersamaan:

```java
public class InventoryTracker {
    private int stock;
    private boolean lowStockAlerted;

    public InventoryTracker(int initialStock) {
        this.stock = initialStock;
    }

    public void reserve(int qty) {
        if (stock >= qty) {
            stock -= qty;
        }
        if (stock < 10 && !lowStockAlerted) {
            lowStockAlerted = true;
            sendLowStockAlert();
        }
    }

    private void sendLowStockAlert() {
        // kirim notifikasi ke tim gudang
    }

    public int getStock() {
        return stock;
    }
}
```

Identifikasi minimal **2 masalah concurrency berbeda** di kode ini (bukan cuma 1), jelaskan masing-masing race condition atau visibility problem (atau dua-duanya), lalu perbaiki. Sertakan alasan kenapa Anda pilih `synchronized`, `volatile`, atau `Atomic*` di tiap titik — bukan cuma "supaya aman", tapi kenapa itu pilihan yang tepat dibanding 2 alternatif lainnya.
    1. reserve() mengalami race condition pada stock

    Bagian ini tidak atomic:

    if (stock >= qty) {
        stock -= qty;
    }

    2. lowStockAlerted juga race condition

    Bagian:

    if (stock < 10 && !lowStockAlerted) {
        lowStockAlerted = true;
        sendLowStockAlert();
    }


    3. getStock() punya visibility problem

    stock biasa dibaca tanpa synchronization:

    public int getStock() {
        return stock;
    }

    Perbaikan yang paling sederhana
    ```java
    public class InventoryTracker {
        private int stock;
        private boolean lowStockAlerted;

        public InventoryTracker(int initialStock) {
            this.stock = initialStock;
        }

        public synchronized void reserve(int qty) {
            if (stock >= qty) {
                stock -= qty;
            }

            if (stock < 10 && !lowStockAlerted) {
                lowStockAlerted = true;
                sendLowStockAlert();
            }
        }

        private void sendLowStockAlert() {
            // kirim notifikasi ke tim gudang
        }

        public synchronized int getStock() {
            return stock;
        }
    }
    ```
    Kenapa synchronized?

    Karena kita tidak hanya membutuhkan atomicity untuk satu variable.

    Kita harus menjaga invariant gabungan:

    if (stock >= qty) {
        stock -= qty;
    }

    if (stock < 10 && !lowStockAlerted) {
        lowStockAlerted = true;
        sendLowStockAlert();
    }

    stock dan lowStockAlerted harus konsisten terhadap satu sama lain.

    sychronized memberikan dua hal sekaligus:

    Mutual exclusion — hanya satu thread yang menjalankan critical section pada satu waktu.
    Visibility / happens-before — unlock monitor terjadi-before lock berikutnya pada monitor yang sama.

**Bagian 2 — Jelaskan singkat.** Rekan Anda bilang: "Saya sudah taruh `synchronized` di method `reserve()`, jadi `getStock()` juga otomatis aman dibaca dari thread lain tanpa perlu diapa-apakan." Benar atau salah? Jelaskan dari konsep *happens-before* kenapa jawaban Anda begitu.

    Salah.

    reserve() yang synchronized hanya menjamin mutual exclusion dan visibility terhadap thread yang juga melakukan synchronization pada monitor yang sama.

    getStock() yang tidak synchronized tidak memiliki hubungan happens-before dengan reserve(). Jadi tidak ada jaminan thread yang memanggil getStock() melihat nilai stock terbaru.

    Karena itu, getStock() juga perlu:

    ```java
    public synchronized int getStock() {
        return stock;
    }
    ```

    Intinya: synchronized pada reserve() tidak otomatis membuat pembacaan oleh getStock() aman.
